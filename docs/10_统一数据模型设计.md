# 第十部分：统一数据模型详细设计（Canonical Data Model）

这是整个企业集成中台最核心的一层。

前面我们解决：

> 如何连接不同厂商

这一部分解决：

> 不同厂商的数据如何变成统一的数据语言


类似：

支付领域：

```text
支付宝订单
微信支付订单

        ↓

Unified Payment Model
```

企业集成：

```text
企业微信 User
飞书 User
钉钉 User

        ↓

Unified User Model
```

---

# 1. Canonical Model 设计原则

## 原则一：只抽象共同能力

例如：

三个平台都有：

- 用户
- 部门
- 消息


进入 Core Model。


---

## 原则二：保留厂商扩展能力


例如：

飞书：

- 多维表格
- Wiki
- 文档块


企业微信：

- 客户联系


不能强行塞进去。


设计：

```text
Core Model

+

Extension Model
```


---

## 原则三：内部 ID 与外部 ID 分离


错误：

```json
{
"user_id":"ou_xxxx"
}
```


因为：

飞书：

```text
ou_xxxx
```


企业微信：

```text
zhangsan
```


钉钉：

```text
userid123
```


正确：

```json
{
"id":"internal_uuid",

"identities":[

]

}
```

# 数据库设计


## user


```sql
CREATE TABLE users
(
 id UUID PRIMARY KEY,

 tenant_id UUID,

 name VARCHAR(128),

 mobile VARCHAR(32),

 email VARCHAR(128),

 avatar TEXT,

 status VARCHAR(32)

);
```

---

## external_identity


```sql
CREATE TABLE external_identity
(
 id UUID,
```

```json
}
```
