# 2. Authentication 身份认证

## 2.1 企业微信认证模型

企业微信主要使用：

```
corp_id
+
secret

↓

access_token
```

API：

```
GET

https://qyapi.weixin.qq.com/cgi-bin/gettoken
```

请求：

```json
{
"corpid":"xxx",
"corpsecret":"xxx"
}
```


返回：

```json
{
"errcode":0,
"errmsg":"ok",
"access_token":"xxx",
"expires_in":7200
}
```

---

# 2.2 中台统一设计

不能暴露：

```
corpsecret
```

设计：

## Credential Model


```json
{
"id":"credential001",

"provider":"wecom",

"tenant_id":"company001",

"config":

{
"corp_id":"xxx",
"secret":"encrypted"
}

}
```

---

统一接口：

```
POST /credentials/connect
```

参数：

```json
{
"provider":"wecom",

"credential":{}
}
```

---

对应：

飞书：

```
app_id
app_secret
```

钉钉：

```
appKey
appSecret
```

统一：

```python
CredentialProvider
```

# 3.3 员工同步机制


不能每次查询企业微信。

应该：

```
Webhook/Event

+
Sync Engine
```


流程：

```
企业微信

user_created

      ↓

Webhook

      ↓

Integration Hub

      ↓

User Sync Service

      ↓

Unified User DB
```


---

统一事件：

```json
{
"type":"user.created",

"provider":"wecom",

"data":

{
"id":"zhangsan"

}

}
```

# 11. 企业微信调研结论


## 高度可抽象：

✅ 用户  
✅ 部门  
✅ 消息  
✅ 文件  
✅ 事件  


## 部分抽象：

⚠️ 客户关系

原因：

企业微信独有。


## 不建议强行统一：

⚠️ 文档

原因：

飞书能力远超过企业微信。
