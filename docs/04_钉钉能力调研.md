# 第四部分：钉钉（DingTalk）API 能力详细拆解

钉钉与企业微信、飞书相比，定位更加偏：

> 企业组织管理 + OA 工作流 + 企业应用生态

因此它在：

- 组织架构
- 用户体系
- 审批
- 考勤
- 待办
- 工作流

方面非常强。

如果构建统一企业 API 中台，钉钉最大的价值是补齐：

> 企业管理能力模型

# 2. Authentication 认证体系

## 2.1 钉钉认证模型


钉钉开放平台主要：

```text
appKey
+
appSecret

↓

access_token
```


接口：

```
POST

/v1.0/oauth2/accessToken
```


请求：

```json
{
 "appKey":"xxx",
 "appSecret":"xxx"
}
```


返回：

```json
{
 "accessToken":"xxx",

 "expireIn":7200
}
```

# 关键架构结论

经过三家平台分析，有一个非常重要的设计原则：

## 不应该设计：

```
企微 API
飞书 API
钉钉 API

↓

统一接口
```

因为会导致能力损失。


---

应该设计：

```
                Capability Model

                       |

        ----------------------------

        Core API

        +

        Capability Extension

                       |

       Adapter Provider
```

例如：

统一：

```
Document.create()
```

不合理。

应该：

```
resource.create()

type=document

capability=document.create
```
