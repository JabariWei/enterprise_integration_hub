# 1. 厂商能力总览

## 1.1 企业微信

企业微信开放能力主要围绕：

- 企业组织管理
- 内部沟通
- 客户关系
- 应用消息
- 企业办公

展开。

官方 API 体系主要包括：

|能力域|说明|
|-|-|
|身份认证|access_token|
|通讯录|成员、部门、标签|
|消息|应用消息、群机器人|
|客户联系|外部联系人、客户群|
|素材管理|图片、文件|
|应用管理|自建应用|
|OA|审批、打卡、会议等|
|事件回调|成员变化、消息事件|

企业微信通讯录 API 支持成员、部门、标签等对象查询、创建、修改、删除。

---

## 1.2 飞书

飞书开放平台能力最完整。

官方开放接口覆盖：

- 通讯录

- 云文档
- 云空间
- 多维表格
- 日历
- 视频会议
- 考勤
- 审批
- 任务
- 邮箱

飞书目前提供大量服务端 API 和事件能力，包括通讯录、消息群组、云文档、多维表格、审批、日历等模块。

## 1.3 钉钉

钉钉开放能力主要：

# 2. 第一层抽象：能力域 Capability Domain

不能直接按照厂商 API 分类。

例如：

飞书：

```
云文档
多维表格
知识库
```

企业微信：

```
素材
文件
```

名字不同。

所以第一层应该定义：

```
Capability
```

---

统一能力：

```
Enterprise Capability Model
```


设计：

```
Capability
|
├── Identity
|
├── Organization
|
├── Messaging
|
├── File
|
├── Document
|
├── Workflow
|
├── Calendar
|
├── Attendance
|
├── Customer
|
├── DataTable
|
└── Event
```

# 3. Identity 身份体系抽象

## 3.1 厂商原始模型


## 企业微信 User


```json
{
 "userid":"zhangsan",
 "name":"张三",
 "mobile":"138xxxx",
 "department":[1,2],
 "position":"销售"
}
```


---

## 飞书 User


```json
{
"user_id":"ou_xxxxx",

"name":"张三",

"mobile":"138xxxx",

"department_ids":[
"dept001"
]
}
```


飞书用户体系存在 user_id、open_id、union_id 等不同身份标识。


---

## 钉钉 User


```json
{
"userid":"12345",

"name":"张三",

"dept_id_list":[1,2],

"mobile":"138xxxx"
}
```


---

# 7. Document 在线文档抽象（重点）


这里不能简单统一。


因为：

飞书：

```
Doc
Sheet
Bitable
Wiki
```

非常强。

企业微信：

基本没有同等能力。


所以设计：

## Document Capability


而不是强制所有平台实现。


---

定义：

```json
{
"capability":

"document",

"operations":[

"create",

"read",

"update",

"delete"

]
}
```


查询：

```
GET /providers/{id}/capabilities
```


返回：

```json
{
"feishu":

[
"document.create",

"sheet.update",

"wiki.search"

]

}
```
